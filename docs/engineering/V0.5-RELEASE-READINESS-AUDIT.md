Re-capture and audit current Light/Dark/Paper, narrow window, table/context-menu, Recent/Search, history/recovery and Source/WYSIWYG states. A visual mismatch affecting use or accessibility blocks release; cosmetic baseline refresh without a product defect may be separately scheduled.

Mark each Passed, Deferred-by-approved-scope, Failed or Missing evidence. No inferred success from a feature title or old worktree.
5. **RR-04/RR-06 — prepare release candidate (P0).** Once product gates permit: version manifests to 0.5.0, lockfile/version/release notes consistency; run exact RC PR CI and three-platform packaging; assemble updater YAML, checksums and artifacts; install/run the produced packages; verify v0.4.1 → v0.5.0 update, unsaved-content safety, existing local history/recovery, failure/retry and no corruption. 6. **RR-07 — visual acceptance (P1).** Replace stale reference screenshots only after reviewing current real UI in Light/Dark/Paper, narrow responsive layouts, editor/table/menus, settings, search and recovery; record approved differences. Do not bless product regressions as visual-baseline changes.
7. **RR-08 — maintenance (P2).** Review each dirty/stale worktree before removal; keep all non-integrated work. Run bounded full object-integrity/GC diagnosis without aggressive prune, keeping backups and repository refs safe.

Go only when the **non-deferred** release gates RR-04/RR-05/RR-06 (and applicable automated CI for RR-03) are backed by **current exact-candidate evidence**, with no unresolved P0 product failures: Windows native/package and real install/upgrade safety, macOS Intel/ARM package and updater artifact automation, release artifact integrity, unchanged Fast Performance Gate and a reviewed change log. Optional P3, cosmetic follow-ups and unrelated maintenance may also remain deferred.

Until then: **NO-GO, no v0.5.0 tag, no release.**

## 6. Audit-stage validation and limitations

This is an evidence audit, **not** a new full Electron, performance, macOS, installer or release execution. Read-only inspection covered Git refs/worktrees, story and architecture records, tag/version/release config, merged PR CI statuses, performance workflow runs and failure logs, runner inventory, updater verification and package smoke scripts. No platform-specific pass, fresh RC performance sample or test coverage not observed here is claimed.

Reusable lesson: **Feature PR green is not version release-green.** Keep per-story integration, target-OS native behavior, reference-hardware performance, artifact assembly and real upgrade safety as separate signed gates. Check branch-only user-story work before declaring a release scope complete.
