### Performance defect: every Backlinks lookup scanned the whole workspace

- Root cause in `MarkdownLinkIndex.getBacklinks`: iterating every indexed document and every link even if the requested target has no backlinks. The heavy path is reachable through the existing sidebar refresh.
- Baseline diagnostic using current worktree TypeScript, known-good donor `tsx@4.22.4` and real `performance.now()`: at 20,000 indexed Markdown sources, a missing target had approximately **23 ms median** across short samples; a heavily linked target cost approximately **31 ms median**. These figures are workstation observations, not reference-machine gate measurements.
- **Valid executed Red:** `node:test` explicitly compared 500 versus 20,000 sources, 12 missing-target lookups per observation, 11 observations per population. Test body entered and failed the sublinear lookup condition: median sample `17.489 ms` versus `937.454 ms`, **53.60× growth**. No production code was changed before this run.
- Implementation: maintain a private target → source → backlink-occurrences inverse lookup. On document update, remove old source contributions and insert parsed target groups; on remove/clear, delete matching inverse entries. Preserve deterministic source-path/source-offset sort, multi-link duplicates and existing standard Markdown parser. Avoid retaining parsed links a second time in the source bookkeeping map. No new IPC, no editor-runtime ownership, no disk writes.
- **Executed Green:** same Node test **1/1 passed**, 500 versus 20,000 sources `0.013 ms` versus `0.009 ms` for equivalent empty lookups (micro-timings near clock precision; do **not** infer a precise speedup factor). A separate executable index correctness check **1/1 passed** for duplicate occurrences, re-targeting, source removal, clear and re-add. Focused Vitest regression cases were added for inverse-index consistency and large-workspace missing-target queries; the latter uses an ample 150 ms total budget across 64 lookups with 12,000 indexed sources, not a modification of any existing Fast Gate or sampling policy.

### Safety defect: directory junction replacement left stale backlinks

- Root cause in `DocumentIntelligenceService.refreshWorkspaceFile`: after validating the real file path, an outside-root parent symlink/junction returned early without retracting the old saved-source contribution.
- **Valid executed Red on Windows:** constructed an ordinary indexed Markdown source under `notes/`, renamed that directory, replaced the original directory with a junction to an external directory, then refreshed the original source path. A real Node test body expected zero backlinks but found **one stale backlink** (`1 !== 0`).
- Implementation: treat an unsafe symlink entry or a physically outside-root resolved source as **no saved workspace source**, allowing the existing per-file invalidation/revision path to retract it. Dirty/open in-memory document overlays remain authoritative. No external Markdown file is read.
- **Executed Green:** the identical Windows filesystem test **1/1 passed** after mutation. A matching Vitest regression was added.
