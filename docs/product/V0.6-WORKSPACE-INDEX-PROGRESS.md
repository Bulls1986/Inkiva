## Stage 2 — Implemented initial capability

- Added an asynchronous, bounded main-process workspace index of standard .md/.markdown documents using existing `MarkdownLinkIndex` rather than a second parser.
- Excludes symlink recursion and common generated folders; limits visited directories (10,000), Markdown files (20,000), individual file bytes (5 MiB) and total indexed file bytes (64 MiB). Skips/errors return `complete: false` and a skipped count; never silently label a partial scan complete.
- Tracks current open-document Markdown overlays separately from saved disk content. Closing a tab restores its saved workspace index entry instead of blindly deleting the backlink source.
- A scan generation prevents an older in-flight scan from replacing the result of a more recent workspace selection.
- Added typed shared IPC channel, handler validation, preload API and renderer coordinator/store workspace root watcher. The coordinator orders scan refresh with editor tab indexing and guards stale selection results; incomplete scans surface the existing sync-error state.
- Adjusted relevant IPC/coordinator/store unit mocks and added a deterministic stale-scan unit scenario.

6. **Partial result UX:** the existing generic `sync` error signals an incomplete scan, but the detailed skipped-file count is not yet surfaced as a dedicated, accessible partial-state message.

## Stage 4 — Owner-scoped multi-window indexing (2026-10-08)

The initial stage proved that a single document-intelligence service was shared by all Electron windows. A separate executable Red case created two workspaces and called `indexWorkspace(A, 11)` then `indexWorkspace(B, 22)`; when querying backlinks for A under owner 11, **expected 1, received 0** (Node `node:test` in current worktree via known-good `tsx` donor executable, 1 failing test **inside the test body**, not a runner failure).

Implementation:

- The singleton Document Intelligence service **continues to own one shared Local History instance** but stores distinct Markdown link indexes, active-tab overlays, workspace disk inventories and cancellation generations for each sender owner id.
- Main IPC handler binds the owner to Electron `event.sender.id` and never accepts an owner ID supplied by the renderer. `webContents.destroyed` drops only that owner's disposable link index. Local History remains process-shared.
- Service default scope `0` retains the existing direct API/test behavior. Typed preload/IPC contracts are otherwise unchanged.
- Added a focused Vitest spec for two scoped workspace roots and added IPC handler routing assertions; canonical Vitest remains blocked as recorded in Stage 3.

Executable Green:

- Multi-window `node:test` after the change: **1/1 passed**; independent scoped backlinks, no cross-window source leaks, scope disposal preserves the other index.
- Post-change combined source regression: **2/2 passed**; workspace disk + dirty-tab override/close/switch and separate IPC owner scopes + input validation.

These are service/handler source probes, **not** Electron window E2E, canonical TypeScript or complete runtime release evidence. Remaining blockers are the external filesystem change lifecycle, partial-state UX, large-workspace responsiveness, actual Electron multi-window acceptance, canonical test environment, and case-sensitive path identity.
