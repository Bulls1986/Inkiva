## Stage 2 — Implemented initial capability

- Added an asynchronous, bounded main-process workspace index of standard .md/.markdown documents using existing `MarkdownLinkIndex` rather than a second parser.
- Excludes symlink recursion and common generated folders; limits visited directories (10,000), Markdown files (20,000), individual file bytes (5 MiB) and total indexed file bytes (64 MiB). Skips/errors return `complete: false` and a skipped count; never silently label a partial scan complete.
- Tracks current open-document Markdown overlays separately from saved disk content. Closing a tab restores its saved workspace index entry instead of blindly deleting the backlink source.
- A scan generation prevents an older in-flight scan from replacing the result of a more recent workspace selection.
- Added typed shared IPC channel, handler validation, preload API and renderer coordinator/store workspace root watcher. The coordinator orders scan refresh with editor tab indexing and guards stale selection results; incomplete scans surface the existing sync-error state.
- Adjusted relevant IPC/coordinator/store unit mocks and added a deterministic stale-scan unit scenario.

## Known blockers and risks before a ready-for-review PR

1. **Multi-window isolation:** the pre-existing main-process `DocumentIntelligenceService` and `linkIndex` singleton share indexing across editor windows. This implementation does not yet scope workspace indexes by sender/webContents, so two windows with different workspaces could interfere. Must be closed before acceptance.
2. **External filesystem reconciliation:** the project root watcher indexes on workspace selection, but does not yet reconnect filesystem create/delete/content updates or a bounded explicit reindex control. A changed unopened file could stay stale until the workspace is re-selected.
3. **Verification topology:** Vitest donor is missing `tinyexec`, package-level launcher is missing, and TypeScript resolves Muya source from another checkout. Use a complete matching dependency graph or canonical CI; never bypass or weaken test gates.
4. **Heavy workspace performance:** scanning/parsing is async for IO but the final in-memory index rebuild is synchronous. The user-visible editor latency/memory budget is **not yet measured**; no performance acceptance should be claimed.
5. **Path identity:** the pre-existing `canonicalDocumentPath` normalizes paths to lowercase on macOS, which is unsafe on case-sensitive volumes. Audit under the V06-01 path contract before claiming cross-platform correctness.
6. **Partial result UX:** the existing generic `sync` error signals an incomplete scan, but the detailed skipped-file count is not yet surfaced as a dedicated, accessible partial-state message.

## Learning review

- Distinguish executable product Red from a launcher failing before test discovery; only the former authorizes production changes.
- A tabs-only index cannot model a workspace. Overlay saved workspace content with open unsaved document content instead of choosing one source forever.
- Background scan cancellation must prevent the already-running stale writer from committing, not merely hide old UI results.
- Reusing a dependency CLI does not make cross-worktree TypeScript source realpaths safe; inspect actual source ownership before relying on its diagnostic output.
- Do not add these as duplicate root AGENTS rules: existing testing/architecture/environment guides already govern them.
