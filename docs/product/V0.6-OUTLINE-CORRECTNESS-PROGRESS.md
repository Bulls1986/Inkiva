## Stage 4 — official Linux E2E finding and guarded focus ownership (2026-10-12)

**Current status:** strict new regression valid Red → focused Green; full local and latest-head official CI pending.

- PR #244 source HEAD `4946ab5820350a24e3cdf4110807c6ef3bbd9930` first reported official Test/Lint/Fast Gate/PR Build success, but initial full E2E was **cancelled by the unchanged 15-minute job cap** after setup dependencies took most of the time. This is runner/setup-duration evidence and not a product assertion.
- The exact E2E job was rerun without code, test, workflow or timeout modification. The second attempt completed **422 passed / 15 skipped / 1 failed**. The only failure was the *new* V06-09 test on Linux: rapid Home → End → Enter left `.editor-component.scrollTop` at 0 instead of navigating to the 340th heading. **This is valid product regression evidence** independent of the first runner timeout.
- Diagnosis: a virtual heading row is a transient DOM focus owner. When Home/End changes the materialized window, its previous treeitem is unmounted; rapid follow-on key events can hit `document.body` before the two-paint item focus transfer completes. The original `handleKeydown` rejected events without a mounted `treeitem`.
- A stable existing `role=tree` root now has `tabindex=-1`; each internal keyboard move synchronously transfers focus to that **stable** root before window re-materialization. Root key events use the currently selected logical `focusedKey` while the distant row is not mounted. After settling, existing two-paint transfer returns focus to the row, guarded by monotonic intent and newer user interactions. Explicit Enter cancels pending focus repaint before sending the navigation intent. This preserves the already-tested Tab entry, row roles, editor geometry ownership and no-focus-theft requirements.
- A new narrow structural regression was added first; Vitest discovered **3 tests, 1 failed / 2 passed** on the pre-fix source. After implementation, focused TOC suites **22/22 passed**. Existing strict Electron 340-heading sequence remains unchanged, including rapid End → Enter and expected actual editor viewport movement.
- Do not use the earlier 3/3 Windows-only result to claim Linux correctness. Before final merge, re-run final local Electron E2E, lint, typecheck, build and official latest-head CI. No threshold, scenario, worker count or timeout will be relaxed.
- Learning: with virtualized interactive items, DOM nodes cannot be the sole keyboard event owners across rapid re-materialization. Keep keyboard ownership on a stable parent during mounting, with explicit intent cancellation, instead of inserting arbitrary sleeps or changing test expectations.
