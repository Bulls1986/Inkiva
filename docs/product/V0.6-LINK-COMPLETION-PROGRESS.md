## Stage 2 — Candidate service, typed IPC and transactional Muya editing

**Implemented:** bounded in-scope completion search using V06-02's existing indexed workspace inventory, watcher updates, document overlay precedence and sender ownership. Original physical filename casing is retained in a parallel bounded pathname map rather than changing the global macOS/Windows canonical-key contract (#229). Open documents in the same workspace supplement the scanned inventory; the source document, external roots, ignored symlinks and non-Markdown targets never become suggestions. Fuzzy ranking prioritizes basename matches, then relative paths and subsequences; suffix-only fuzzy false positives are excluded.

**Typed boundary:** the new `searchWorkspaceLinkCandidates(sourcePath, query)` travels via the registered shared document-intelligence channel through main IPC handler, per-sender service and preload domain API. No renderer direct filesystem scans or raw channel strings. The IPC validates both source and query arguments.

**Muya behavior:** extend existing link format operation with an optional destination argument, preserving empty-link semantics for existing callers. For selected text, destination commits atomically in the engine's one `runUserOperation`. For existing standard inline links, retarget only the supported syntax while preserving the label/title and keeping edits inside one history operation. No new Markdown syntax or editor ownership.
