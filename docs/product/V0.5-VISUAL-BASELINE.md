## Goal and acceptance boundary

Adopt a **real application screenshot baseline**, not a design mockup or a
blind snapshot refresh. A screenshot becomes approved only after:

1. the exact release/code revision, host OS, appearance, window dimensions and
   test fixture are reproducible;
2. the associated Electron flow reaches a real, observable UI-ready state;
3. the image is inspected for clipping, overlap, copy/localization consistency,
   command placement, caret/selection problems, and unintended visibility;
4. any deviation from the v0.5 interaction contract is classified as a
   product defect and fixed **before** approving a reference image;
5. the reviewed image is checked into the per-OS Playwright screenshot directory
   and a subsequent non-update regression test passes without relaxing
   `maxDiffPixelRatio: 0.005` or skipping cases.

The Linux screenshots are CI pixel references, **not** proof of macOS native
titlebar or IME correctness. Native macOS manual acceptance remains explicitly
deferred as agreed for v0.5.0.

## Review focus

- **Themes**: text contrast, document surface, left/right chrome, overlays.
- **550 / 768 px**: no collision of search, titlebar, controls or editor;
  hiding/collapsing secondary controls is acceptable when discoverable.
- **Table/context menu**: no duplicated actions, overflow or legacy
  spreadsheet-like affordances; mouse context must correspond to the cell.
- **Source mode**: no WYSIWYG serialization artifacts presented as normal text;
  literal syntax is expected only in Source mode.
- **Recent/search**: command search authority is the sidebar/command palette,
  not a conflicting titlebar hotkey hint; visible recent items remain usable.
- **Recovery/history**: comparison and decision actions must be legible and
  non-destructive until explicitly confirmed; historical data remains safe.

## Reusable lesson

Visual snapshots are acceptance **evidence**, not automatic authorization to
change the product standard. First prove the live screen and its interaction
contract; then inspect pixels; only then bless the reference image. Keep
fixture and screenshot lifecycle in one named, resumable record.
