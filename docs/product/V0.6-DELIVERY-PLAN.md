# Inkiva v0.6.0 — Delivery Plan / Task Breakdown

Status: **Planned / not started**  
Planning date: 2026-10-08  
Base: latest remote `develop` (v0.5.0 version line)  
Scope: Document Navigation & Asset Experience; no AI  
Owner: Product + Editor / Desktop Engineering  
Tracking: V06-00…V06-15 (planning identifiers, **not yet GitHub Issue numbers**)

## 1. Outcome and boundary

Make standard Markdown documents easier to connect, navigate and maintain, while keeping Inkiva a fast, document-first desktop editor. Do not introduce wiki syntax, a graph database, a cloud sync service, automatic link rewrites without review, spreadsheet-style table features, or new file-ownership/storage authorities.

The durable `docs/product/DESKTOP_EDITOR_INTERACTION_CONTRACT.md` remains authoritative for editing, focus, keyboard, IME, table and window behavior; read the relevant ARCH contracts before any production edit. The Markdown file is always the source of truth. Derived indexes are disposable, revision-aware and cancellable; navigation cannot preempt current editor intent.

## 3. Task backlog

All estimates are *person-days of scoped engineering effort*, including focused tests and local closeout, **not** elapsed wall clock or verified benchmarks. Baseline review may close tasks without implementing them. One task = one coherent PR; several independent small subcases may be grouped only when they share a single contract.

### V06-01 — Navigation/path/interaction contract | P0 | 2d | after V06-00

- Specify relative path encoding, fragment handling, case sensitivity, file identity, workspace boundaries, Unicode and special characters.
- Define intentional open vs edit, caret/focus handoff, keyboard/IME suppression, autocomplete dismissal, empty/error states, and accessible feedback.
- Define link diagnostics taxonomy: missing local file, missing fragment, unsupported/external target, permission denied, inaccessible workspace; never silently rewrite source.
- Decide whether fragment verification belongs in v0.6 based on evidence, without broadening into a Markdown language server.
- **Acceptance:** example-driven normative product contract plus negative/cancel/undo flows; existing `Ctrl/Cmd+K` keeps hyperlink authority.
- **Dependencies:** V06-00.

### V06-02 — Workspace-scoped link index / lifecycle | P0 | 4d | after V06-01

- Diagnose whether the current index can resolve unopened Markdown files inside the explicitly opened workspace; only implement missing scope.
- Build on `MarkdownLinkIndex` + `DocumentIntelligenceService`; keep main/preload/renderer typed boundaries. No second document source of truth.
- Bounded scan / cache invalidation / saved-vs-dirty revision preference; handle rename/move/delete, tab close, workspace switch, symlinks and unreadable files.
- Schedule discovery away from editor hot paths; cancellation, freshness and lifecycle closure are mandatory.
- **Acceptance:** backlinks across unopened documents are correct after workspace open/restart/file changes; no duplicate/stale entries; tests prove cancellation and no cross-workspace leakage.
- **Tests:** parser/index unit → service/integration → one focused Electron workspace lifecycle flow.
- **Dependencies:** V06-01; unlocks V06-03/05/06/08.

### V06-03 — Link insertion + document candidate completion | P0 | 3d | after V06-02

- Wire existing candidate IPC into an intentional user-facing hyperlink insertion/edit flow; no competing global search and no replacement of `Ctrl/Cmd+K`.
- Fuzzy-match workspace Markdown files, display disambiguating paths, emit standard relative Markdown destinations with percent-encoding where required.
- Preserve selection/caret, document identity, one logical Undo; suppress during IME composition; Escape cancels without mutation.
- **Acceptance:** selecting a candidate inserts/updates exactly one standard Markdown link; duplicate basenames distinguishable; source/WYSIWYG round-trip and no stale popup.
- **Tests:** path/candidate unit + targeted editor integration + one Electron command/focus E2E.
- **Dependencies:** V06-01, V06-02.

### V06-04 — Link navigation and target positioning | P0 | 3d | after V06-01

- Verify document path links, same-file fragments, cross-file fragments and backlinks: distinguish a click for editing from deliberate navigation.
- Preserve tab/session unsaved state, caret intent, history and viewport; missing/inaccessible target gives recoverable feedback.
- Handle virtualized target headings and stale asynchronous target resolves without scroll/focus rollback.
- **Acceptance:** exact target document and heading are revealed when reachable; no accidental navigation during ordinary selection; tab/source round-trip preserves content.
- **Tests:** focused navigation mapping + Electron link/focus/virtualization scenarios.
- **Dependencies:** V06-01; coordinate with V06-02 for cross-workspace behavior.

### V06-05 — Backlinks completeness + UI | P0 | 2d | after V06-02, V06-04

- Verify results include actual workspace references, including unopened files, while maintaining correct open-tab dirty buffer precedence.
- Preserve source identity and click-to-reference navigation; distinguish no-backlinks / loading / scan-error states; avoid duplicate UI surfaces.
- **Acceptance:** open/closed/moved/deleted sources reconcile deterministically; navigation goes to the source occurrence, without destroying the current draft.
- **Tests:** index/coordinator unit + focused sidebar/navigation E2E.
- **Dependencies:** V06-02, V06-04.

### V06-06 — Broken local Markdown link diagnostics | P0 | 3d | after V06-02

- Reuse the canonical parser/path resolver and index, never create a second parser/index to derive diagnostics.
- Detect missing local Markdown targets; classify missing fragment only if V06-01 defines reliable portable slug semantics; external/unsupported links are not blindly flagged.
- Report source path, offset/line, destination, reason and stable revision; reject stale diagnostics after edits/workspace changes.
- **Acceptance:** deterministic detection over specified workspace fixtures; false positives excluded for code spans/fences/front matter, malformed syntax, encoding and case-policy cases.
- **Tests:** pure/parser unit + filesystem adapter integration; one user-facing E2E after V06-07.
- **Dependencies:** V06-01, V06-02.

### V06-07 — Broken-link locate/repair workflow | P1 | 2d | after V06-06

- Surface diagnostics in an existing relevant sidebar/context (not an unrelated new top bar).
- Navigate to source and offer explicit edit/choose-target action; no automatic filesystem-wide rewriting or destructive cleanup.
- Cancellation and failed edits are zero mutation; repair uses a standard Markdown destination and one Undo unit.
- **Acceptance:** click report → exact source → deliberate repair → diagnostics refresh; inaccessible paths remain explainable, IME/focus preserved.
- **Tests:** scoped editor integration + one Electron end-to-end repair scenario.
- **Dependencies:** V06-06, V06-03/04.

### V06-08 — Rename/move repair consistency | P0 | 3d | after V06-02

- Audit current `renameRepair.ts` before implementing. Cover source/target moved together, nested directories, spaces/Unicode, case-only rename, fragments, new external edits, read-only files and mid-operation failure.
- Show affected files/count and explicit update / keep / cancel choices. Respect source revision and unchanged disk bytes on cancellation/conflict.
- Preserve Local History and original file identity; do not introduce a second filesystem writer/rollback authority.
- **Acceptance:** no partial silent overwrite, unchanged links are byte-preserved, intentional decisions are reflected across index/backlinks and reopen.
- **Tests:** pure repair-plan + file-adapter failure injection + one Electron rename/move route.
- **Dependencies:** V06-01, V06-02.

### V06-09 — Outline UX and correctness closure | P1 | 2d | after V06-01

### Scope / release policy

- **Must ship:** correct workspace link index (when audit confirms gap), link creation, navigation, backlinks, broken-link detection, link maintenance, preservation of v0.5 editing correctness.
- **Conditional/minimal:** image, table and Outline implementations only when executable evidence shows a gap. Their regression acceptance remains mandatory.
- **No v0.6 scope:** AI assistance; wiki-link proprietary format; graph visualization; cloud sync; plugin ecosystem; automatic mass deletion of unused assets; bulk Markdown rewrite without preview/guard; Excel-style table extensions.
- **Hard stop:** missing executed Red test before production mutation, architecture-boundary violation, data-loss risk, unresolved P0 correctness failure, or a false CI/performance pass claim.

## 6. PR / CI / stage-document execution protocol

1. Before each PR, obtain latest **remote** `develop`, create one isolated worktree/branch, read `AGENTS.md`, `docs/agent/TESTING.md`, `docs/agent/ARCHITECTURE_RELEASE.md`, and affected ARCH/product contracts. Planning/documentation-only changes do not need invented Red behavior evidence.
2. For feature changes, define and **execute** a focused failing product-behavior test before production mutation; environment/bootstrap failures are not Red. Then implement smallest coherent Green.
3. Layer tests by cost: pure parser/index/selection at unit level; filesystem IPC/lifecycle at integration level; only native interaction and multi-process effects in Electron E2E. Reuse existing suites rather than expanding the global E2E lane for each bug.
4. CI remains authoritative for required checks. Preserve performance workloads/thresholds, release package correctness, Windows/macOS build targets, Linux screenshot baseline and documented platform distinctions.
5. Each completed stage updates this plan and a scoped stage record (completed, unfinished, blockers/root cause, red/green/performance evidence, branch/PR, next action). End every task with lessons review and deduplicate agent rules.
6. PR ready != merged. Only squash merge by explicit authorization, then verify merged PR and authoritative remote branch ref. Do not mark version complete upon creating a PR.
