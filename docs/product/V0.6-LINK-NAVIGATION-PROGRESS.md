## Stage 8 — Queued navigation vs later trusted editor gesture (2026-10-09)

- Audited §5 of the V06 link-navigation contract: a source-document **scroll** after click must cancel an in-flight cross-file navigation, even if the document id and content revision do not change. Previous implementation checked only source tab/revision until activation; the editor-local gesture guard started **after** target activation, so a pre-load scroll could be lost.
- **Executed Red:** `node --test packages/desktop/test/unit/link-navigation-origin.test.mjs packages/desktop/test/unit/link-navigation-intents.test.mjs`. Both new LINK-AC06 cases failed at their intended product assertions: `isLinkNavigationOriginCurrent` accepted a changed trusted interaction revision, and the queued request failed to carry the latest gesture revision.
- Reused the existing `renderer/services/editorInteraction.ts` module instead of adding a second interaction state owner. A new **nonreactive trusted editor gesture epoch** is advanced by `editor.vue`'s existing `event.isTrusted`-gated pointer/keyboard/wheel/touch listener and used by its existing delayed-render cancellation. Do **not** use the pre-existing scroll-event epoch for this: layout restores can create synthetic scroll events without user intent.
- Carry the token as transient source navigation metadata through the existing typed renderer/main/open-tab handoff, update it atomically on later clicks, compare at target activation, and strip it from persisted document/tab options. No new filesystem, runtime semantics or reactive hot-path ownership.
- **Focused Green:** navigation Node suites **11/11 passed**; `git diff --check` passed. The full remote CI for this additional code is **pending**, so prior `7058c7e` CI passes cannot be reused as acceptance evidence. Keep PR #235 draft until all latest-head gates pass.
